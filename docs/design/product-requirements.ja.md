# Kiwumil 製品要求仕様書 v1

## 0. 文書目的

本書は Kiwumil を単なる OSS ライブラリとしてではなく、**どのような課題を解決する製品か** を明文化するための製品要求仕様書である。

---

## 1. 製品定義

> Kiwumil は、テキストベース運用とプレゼン品質の図表現を両立する
> **Semantic Diagram Platform** である。

ユーザーはコードで図を記述し、見た目品質の高い図を自動生成し、
継続的に編集・保守できる資産として再利用できる。

---

## 2. 背景課題（市場課題）

### BP-0001 図がレビューしづらい

GUIツールで作った図は差分比較しにくい。

- 何が変わったかわからない
- Pull Request レビューしづらい
- 履歴管理が弱い

### BP-0002 図が保守されない

図は一度作られて古くなりやすい。

- 実装と乖離する
- 更新コストが高い
- 放置される

### BP-0003 図が見た目中心で意味を持たない

図形はあるが意味構造が弱い。

- 依存関係解析できない
- 自動変換できない
- AI利用しづらい

### BP-0004 レイアウト調整が高コスト（最重要課題）

PlantUML や Mermaid はテキストベースで更新しやすい一方、
経営層向け・外部向け資料に必要な整列や見た目品質で限界がある。

GUIツールは見た目品質を確保しやすい一方、変更のたびに手作業更新が必要になる。

その結果、図作成時間の多くが整列・配線調整に使われる。

### BP-0005 図法ごとにツールが分断される

- UML はこのツール
- AWS 図は別ツール
- 業務フローは別ツール

学習コストと移行コストが高い。

## 5. 中核価値（Core Value Proposition）

### PR-0001 Diagram as Code

図をコードとして管理できること。

提供価値:

- Git管理
- 差分レビュー
- 自動生成
- テンプレート化

### PR-0002 Semantic First

図形ではなく意味構造を主語に記述できること。

提供価値:

- モデル変換
- 分析
- AI入力
- 他形式出力

### PR-0003 Presentation Quality Automation

座標指定なしで、資料提出可能な視覚品質の図を生成できること。

提供価値:

- 整列作業削減
- 配線調整削減
- 作図時間短縮
- 修正容易
- 大規模図対応

### PR-0004 Extensible Vocabulary

ドメイン語彙を追加できること。

提供価値:

- UML
- C4
- AWS
- ER
- SysML

### PR-0005 Developer Workflow Native

開発ワークフローに自然統合できること。

提供価値:

- CLI
- CI/CD
- Markdown埋込
- 自動ドキュメント生成

## 6. 製品要求（USDM形式）

### RQ-0001 既存開発環境で図を記述できる

誰が: エンジニアが  
何を: 汎用プログラミング言語を用いて、既存の開発環境内で図を記述できる  
なぜ: 既存の開発フローとツールを活用し、継続的に図を作成・更新したいから

### RQ-0002 意味構造を保持できる

誰が: 設計者が
何を: 図を意味モデルとして保持できる
なぜ: 図の要素や関係を機械的に解釈でき、変換・分析・継続利用をしやすくしたいから

### RQ-0003 描画プリミティブによる図生成

誰が: 利用者が  
何を: 図はDP-0001で定義される描画プリミティブの組み合わせにより表現されること  
なぜ: 図の視覚表現を一貫した低レイヤー描画基盤に変換するため

### RQ-0004 拡張できる

誰が: Plugin開発者が
何を: 独自図法を追加できる
なぜ: 現場ごとの図要求に対応したいから

### RQ-0005 開発フローへ統合できる

誰が: チームが
何を: CI/CD や文書生成へ組み込める
なぜ: 図を継続運用したいから

### RQ-0006 図の意味モデルから描画可能な図への変換

誰が: 利用者が
何を: 図の意味モデル（抽象構造）を入力として受け取り、それを一貫した規則に基づき描画可能な図（レンダリング可能な表現）へ変換できる
なぜ: 意味構造と描画結果の対応を一貫させ、再現可能で差分管理可能な図生成を実現したいから

### RQ-0007 実行結果が決定的である

誰が: 利用者が  
何を: 同一のモデル記述に対して同一の図生成結果を得られる  
なぜ: 差分レビューや再現性を確保したいから


### RQ-0008 レイアウト意図を指定できる

誰が: 利用者が  
何を: 図の要素配置、グルーピング、および相対位置関係に関する意図を指定できる
なぜ: 自動生成では満たしきれない表現上の要求を調整し、資料品質を確保したいから

### RQ-0009 レイアウト意図の解決規則

誰が: 利用者が  
何を: 複数のレイアウト意図が競合または矛盾する場合において、それらを解決する規則が定義されており、一貫した結果が得られる  
なぜ: 利用者の意図を安定して反映し、予測可能な図生成を実現したいから

### RQ-0010 レイアウト意図の抽象度

誰が: 利用者が  
何を: レイアウト意図を相対関係として記述できる
なぜ: 図の保守性と再利用性を確保したいから

### RQ-0011 レイアウト意図の自然言語入力と構造化変換

誰が: 利用者が
何を: 英語ベースの自然言語でレイアウト意図を記述でき、その内容が構造化されたレイアウト制約へ変換される
なぜ: 利用者が直感的に意図を記述しつつ、システム内部では一貫した制約モデルとして処理できるようにしたいから

### RQ-0012 エッジ経路の通過制約指定

誰が: 利用者が  
何を: 接続線について、特定の経路（例: 幹線）または領域を通過するように制約を指定できる。また、他のレイアウト意図と競合する場合においても、一貫した規則に基づいて解決される
なぜ: 図全体の構造や視線誘導を制御し、配線の可読性と資料品質を向上させたいから

## 6.1 用語定義（Rendering Primitives）

本節は製品要求で使用される基礎概念を定義する。

### DP-0001 描画プリミティブ（Drawing Primitive）

描画プリミティブとは、図の最終描画における最小構成単位である。

描画プリミティブは以下の特徴を持つ：

- 意味構造（ノード・エッジ・関係性）を持たない
- レイアウト制約（相対配置・整列ルール）を持たない
- 幾何情報のみを持つ（位置・サイズ・形状）

---

### DP-0002 標準プリミティブセット

本製品は少なくとも以下のプリミティブをサポートする：

- rectangle（矩形）
- text（テキスト）
- circle（円）
- ellipse（楕円）
- icon（アイコン）

---

### DP-0003 プリミティブの責務

描画プリミティブは以下のみを責務とする：

- 幾何的形状の保持
- 描画属性（色・線幅・フォントなど）の保持

プリミティブは以下を持たない：

- 意味的関係
- レイアウト制御ロジック
- 制約解決ロジック

### DP-0004 経路制約要素（Routing Guide / Path Guide）

エッジ経路の誘導のために定義される抽象的な経路または領域
ノードとは独立に定義される
エッジはこれを参照して経路決定される
ただし、最終的な経路は他の制約との整合のもとで決定される

### 6.2 幾何整合性の定義（任意だが強く推奨）

描画可能な図とは、すべての要素が視覚的に配置され、
接続関係が表現され、レンダリング処理に入力可能な状態を指す。

- すべての数値は有限値であること
- サイズは非負であること
- 座標は有限範囲に収まること
- 不定状態を持たないこと

## 7. 非機能要求

### NQ-0001 再現性

同一入力に対して、図生成結果が決定的であること。

### NQ-0002 性能

モデル変更から図生成完了までの時間が、利用者の作業を阻害しない範囲であること。

### NQ-0003 可読性

生成図は、要素の重なりがなく、接続関係が識別可能であり、ラベルが視認可能であり、接続線が追跡可能であること。

### NQ-0003b 資料転用性

出力した図を、大幅な再加工なしに説明資料・提案資料へ利用できること。

### NQ-0004 拡張性

出力形式や語彙拡張を追加可能な構造であること。

### NQ-0005 保守性

継続的な機能追加および修正が可能であること。

### NQ-0006 レイアウト一貫性

図の配置は、モデルの関係およびレイアウト意図のみに基づいて決定され、外部状態に依存しないこと。

### NQ-0007 レイアウト記述の宣言性

レイアウト意図は、要素間の関係または制約として記述可能であること。

### NQ-0008 幾何的整合性保証および視覚最適性非保証

すべての描画結果は幾何的に有効であり、レンダリング可能な状態であること。

## 9. 既存手段では満たしにくい要求

| 手段カテゴリ | 代表例 | 満たしにくい要求 | Kiwumil の提供価値 |
|---|---|---|---|
| 専用モデリングツール | Astah UML, Enterprise Architect など | 特定図法以外への展開、開発フロー統合、継続的なコード管理 | 汎用言語ベースの記述 + 拡張機構 |
| GUI作図ツール | PowerPoint, Draw.io, Visio など | 差分管理、自動生成、変更追従、継続保守 | テキストベース運用 + 自動生成 + 高品質レイアウト |
| テキスト図ツール | PlantUML, Mermaid など | 資料利用に耐える見た目品質、柔軟な表現、型安全な記述体験 | 高品質生成 + TypeScript表現力 + Semantic拡張 |

## 10. 製品原則

1. 図形より意味を優先する
2. 手作業より自動化を優先する
3. 座標より関係性を優先する
4. 一度描くより継続保守を優先する
5. 単一図法より拡張性を優先する
