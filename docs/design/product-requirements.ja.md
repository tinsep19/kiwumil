# Kiwumil 製品要求仕様書 v1

## 0. 文書目的

本書は Kiwumil を単なる OSS ライブラリとしてではなく、**どのような課題を解決する製品か** を明文化するための製品要求仕様書である。

---

## 1. 製品定義

> **Kiwumil は、テキストベース運用とプレゼン品質の図表現を両立する Semantic Diagram Platform である。**

ユーザーはコードで図を記述し、見た目品質の高い図を自動生成し、継続的に編集・保守できる資産として再利用できる。

---

## 2. 背景課題（市場課題）

### BP-01 図がレビューしづらい

GUIツールで作った図は差分比較しにくい。

- 何が変わったかわからない
- Pull Request レビューしづらい
- 履歴管理が弱い

### BP-02 図が保守されない

図は一度作られて古くなりやすい。

- 実装と乖離する
- 更新コストが高い
- 放置される

### BP-03 図が見た目中心で意味を持たない

図形はあるが意味構造が弱い。

- 依存関係解析できない
- 自動変換できない
- AI利用しづらい

### BP-04 レイアウト調整が高コスト（最重要課題）

PlantUML や Mermaid はテキストベースで更新しやすい一方、経営層向け・外部向け資料に必要な整列や見た目品質で限界がある。

GUIツールは見た目品質を確保しやすい一方、変更のたびに手作業更新が必要になる。

その結果、図作成時間の多くが整列・配線調整に使われる。

### BP-05 図法ごとにツールが分断される

- UML はこのツール
- AWS 図は別ツール
- 業務フローは別ツール

学習コストと移行コストが高い。

## 4. プロダクトビジョン

Kiwumil は、

**テキストベース管理の継続性**  
**資料利用に耐える見た目品質**  
**TypeScript の表現力**  
**意味構造による拡張性**

を統合し、開発文書から経営層向け資料まで一貫して扱える次世代 Diagram as Code 基盤を目指す。

---

## 5. 中核価値（Core Value Proposition）

### PR-01 Diagram as Code

図をコードとして管理できること。

提供価値:

- Git管理
- 差分レビュー
- 自動生成
- テンプレート化

### PR-02 Semantic First

図形ではなく意味構造を主語に記述できること。

提供価値:

- モデル変換
- 分析
- AI入力
- 他形式出力

### PR-03 Presentation Quality Automation

座標指定なしで、資料提出可能な見た目品質の図を生成できること。

提供価値:

- 整列作業削減
- 配線調整削減
- 作図時間短縮
- 修正容易
- 大規模図対応

### PR-04 Extensible Vocabulary

ドメイン語彙を追加できること。

提供価値:

- UML
- C4
- AWS
- ER
- SysML

### PR-05 Developer Workflow Native

開発ワークフローに自然統合できること。

提供価値:

- CLI
- CI/CD
- Markdown埋込
- 自動ドキュメント生成

## 6. 製品要求（USDM形式）

### RQ-01 既存開発環境で効率的に図を記述できる

誰が: エンジニアが\
何を: プログラミング言語を用いて、既存の開発環境の中で効率的に図を記述できる\
なぜ: 学習済みの開発体験のまま効率よく図を作成・変更し、品質高く継続運用したいから

### RQ-02 意味構造を保持できる

誰が: 設計者が\
何を: 図を意味モデルとして保持できる\
なぜ: 図の要素や関係を機械的に解釈でき、変換・分析・継続利用をしやすくしたいから

### RQ-03 見た目品質の高い図を自動生成できる

誰が: 利用者が\
何を: 整列され配線品質の高い図を自動生成できる\
なぜ: 手作業整形を減らし、そのまま説明資料に使いたいから

### RQ-04 拡張できる

誰が: Plugin開発者が\
何を: 独自図法を追加できる\
なぜ: 現場ごとの図要求に対応したいから

### RQ-05 開発フローへ統合できる

誰が: チームが\
何を: CI/CD や文書生成へ組み込める\
なぜ: 図を継続運用したいから

## 7. 非機能要求

### NQ-01 再現性

同一入力に対して、利用者が差分レビュー可能な程度に安定した出力となること。

### NQ-02 性能

日常的な開発作業を阻害しない応答時間で図生成できること。

### NQ-03 可読性

生成図は、要素配置・接続線・ラベル配置が視覚的に整理されていること。

### NQ-03b 資料転用性

出力した図を、大幅な再加工なしに説明資料・提案資料へ利用できること。

### NQ-04 拡張性

出力形式や語彙拡張を段階的に追加可能な構造であること。

### NQ-05 保守性

責務分離された構造により継続開発しやすいこと。

## 9. 既存手段では満たしにくい要求

| 手段カテゴリ | 代表例 | 満たしにくい要求 | Kiwumil の提供価値 |
|---|---|---|---|
| 専用モデリングツール | Astah UML, Enterprise Architect など | 特定図法以外への展開、開発フロー統合、継続的なコード管理 | 汎用DSL + Plugin拡張 + 開発環境統合 |
| GUI作図ツール | PowerPoint, Draw.io, Visio など | 差分管理、自動生成、変更追従、継続保守 | テキストベース運用 + 自動生成 + 高品質レイアウト |
| テキスト図ツール | PlantUML, Mermaid など | 資料利用に耐える見た目品質、柔軟な表現、型安全な記述体験 | 高品質生成 + TypeScript表現力 + Semantic拡張 |

---

## 10. 製品原則

1. 図形より意味を優先する
2. 手作業より自動化を優先する
3. 座標より関係性を優先する
4. 一度描くより継続保守を優先する
5. 単一図法より拡張性を優先する
